1 rglob("SKILL.md") — 递归文件查找

📍 代码位置

s05_skill_loading.py#L50
一句话：rglob 递归地找所有子目录中匹配模式的文件，glob 只找当前目录。 
for path in sorted(self.skills_dir.rglob("SKILL.md")):

📍 glob vs rglob 对比

方法搜索范围示例
Path.glob("SKILL.md")仅当前目录skills/SKILL.md ✅
skills/sub/SKILL.md ❌
Path.rglob("SKILL.md")递归所有子目录skills/SKILL.md ✅
skills/sub/SKILL.md ✅

📍 举例

skills/
├── code-review/
│   └── SKILL.md          ← rglob 找到
├── git-workflow/
│   └── SKILL.md          ← rglob 找到
└── mcp/
    └── builder/
        └── SKILL.md       ← rglob 也能找到（递归）

📍 为什么要加 sorted()？

保证加载顺序是确定性的（按路径字母排序），避免因文件系统返回顺序不确定导致行为不一致。

3 re.DOTALL — 让 . 匹配换行符

📍 代码位置

s05_skill_loading.py#L58
一句话：默认 . 不匹配 \n，加上 re.DOTALL 让 . 能匹配包括换行符在内的所有字符。 
match = re.match(r"^---\n(.*?)\n---\n(.*)", text, re.DOTALL)

📍 对比效果

标志. 的匹配范围re.match(r"(.*)", "a\nb")
无（默认）除 \n 外的所有字符只匹配到 "a"
re.DOTALL包括 \n 的所有字符匹配 "a\nb"

📍 在这个场景的具体作用

# 文本内容：
---
name: code-review
description: Review code
---
Here is the body...

正则：r"^---\n(.*?)\n---\n(.*)"
                 ↑         ↑
            group(1)     group(2)
          (frontmatter)  (body)

# 没有 re.DOTALL：
#   (.*?) 中 . 不能匹配换行 → 无法跨行捕获 frontmatter

# 有 re.DOTALL：
#   (.*?) 非贪婪跨行匹配 frontmatter 所有行
#   (.*)  贪婪跨行匹配剩余 body 所有行

📍 非贪婪 .*? vs 贪婪 .*

写法匹配行为在这个正则中
(.*?)尽可能少匹配遇到第一个 \n---\n 就停 → 正确截取 frontmatter
(.*)尽可能多匹配如果没有 ?，可能匹配到最后一个 --- → 出错
注意：re.DOTALL 也叫 re.S，两者是等价的。

4 splitlines() — 无参调用

📍 代码位置

s05_skill_loading.py#L63
一句话：splitlines() 按行拆分并去掉换行符，默认参数就是无参。 
for line in match.group(1).strip().splitlines():

📍 参数区别

写法是否保留换行符示例："a\nb".split???
.splitlines()❌ 去掉["a", "b"]
.splitlines(True)✅ 保留["a\n", "b"]
.splitlines(keepends=True)✅ 保留["a\n", "b"]

📍 为什么这里不需要传参？

frontmatter 里的每一行例如 "name: foobar"，解析 key/value 时只需要纯文本内容，不需要末尾的 \n。所以用默认的 splitlines() 最简洁正确。

📍 5.1 数据结构：SkillManifest + SkillDocument

@dataclass
class SkillManifest:
    name: str          # 技能名称
    description: str   # 技能描述
    path: Path         # SKILL.md 文件路径

@dataclass
class SkillDocument:
    manifest: SkillManifest  # 清单对象（轻量）
    body: str               # 正文内容（昂贵）
类作用放在哪大小
SkillManifest技能的轻量元信息system prompt 的目录很小
SkillDocument完整的技能文档（清单+正文）调用 load_skill 后才进入上下文可能很大
设计意图：第 1 层（manifest）轻量，常驻 system prompt；第 2 层（body）昂贵，按需加载。这就是"两层模型"。

📍 5.3 _load_all() — 扫描并加载所有 SKILL.md

def _load_all(self) -> None:
    if not self.skills_dir.exists():   # ① 目录不存在就跳过
        return
    for path in sorted(self.skills_dir.rglob("SKILL.md")):  # ② 递归找所有 SKILL.md
        meta, body = self._parse_frontmatter(path.read_text())  # ③ 解析 frontmatter
        name = meta.get("name", path.parent.name)             # ④ 取 name（默认目录名）
        description = meta.get("description", "No description")
        manifest = SkillManifest(name=name, description=description, path=path)
        self.documents[name] = SkillDocument(manifest=manifest, body=body.strip())  # ⑤ 存入字典
步骤作用
① if not .exists()skills 目录不存在时优雅跳过，不报错
② rglob("SKILL.md")递归查找所有 SKILL.md 文件
③ _parse_frontmatter()解析 frontmatter，返回 (meta字典, body字符串)
④ .get(key, default)取元数据，没有就用默认值（约定优于配置）
⑤ self.documents[name] = ...存入字典，同名的后覆盖前

📍 5.4 _parse_frontmatter() — 解析 frontmatter

def _parse_frontmatter(self, text: str) -> tuple[dict, str]:
    match = re.match(r"^---\n(.*?)\n---\n(.*)", text, re.DOTALL)
    if not match:                          # 没有 frontmatter → 整个文件是 body
        return {}, text

    meta = {}
    for line in match.group(1).strip().splitlines():  # 逐行解析元数据
        if ":" not in line:                       # 不含冒号的行跳过
            continue
        key, value = line.split(":", 1)               # 按第一个 : 分割
        meta[key.strip()] = value.strip()           # 去除两侧空白后存储
    return meta, match.group(2)                    # 返回 (元数据字典, body)

📍 解析的格式

---
name: code-review
description: Review code changes
---
这里是技能的正文内容...

📍 split(":", 1) 中的 1 是什么？

限制只分割一次。例如：

"description: This is: a test".split(":")     # → ["description", " This is", " a test"]  三段
"description: This is: a test".split(":", 1)  # → ["description", " This is: a test"]  两段，value 保留内容中的 :

📍 为什么不直接用 YAML 解析库？

因为 frontmatter 只有简单的 key: value 格式，没必要引入 PyYAML 等依赖。手写解析足够且零依赖。

📍 5.5 describe_available() — 生成技能目录

def describe_available(self) -> str:
    if not self.documents:
        return "(no skills available)"
    lines = []
    for name in sorted(self.documents):
        manifest = self.documents[name].manifest
        lines.append(f"- {manifest.name}: {manifest.description}")
    return "\n".join(lines)

示例输出：

- code-review: Review code changes
- git-workflow: Branch and commit guidance
- test-gen: Generate test cases for Python code

这段文本会被注入到 system prompt 中，让 AI 知道有哪些技能可用。

📍 5.6 load_full_text() — 按名加载技能正文

def load_full_text(self, name: str) -> str:
    document = self.documents.get(name)          # 用 .get 而不是 []，避免 KeyError
    if not document:
        know = ", ".join(sorted(self.documents)) or "(none)"
        return f"Error: Unknown skill '{name}'. Available skills: {know}"

    return (
        f"<skill name=\"{document.manifest.name}\">\n"
        f"{document.body}\n"
        "</skill>"
    )
场景返回值
技能存在用 <skill> XML 标签包裹的完整正文
技能不存在错误提示 + 列出所有可用技能名
设计意图：describe_available() 生成轻量的目录（常驻 system prompt），load_full_text() 加载完整正文（按需注入）。"先轻发现，再深加载"。

📍 5.9 工具函数（s04 继承 + 精简）

safe_path() — 路径穿越防护：

def safe_path(p: str) -> Path:
    path = (WORKDIR / p).resolve()
    if not path.is_relative_to(WORKDIR):
        raise ValueError(f"Path escapes workspace: {p}")
    return path

run_read() — 安全读取，支持行数限制 + 50000 字符截断：

def run_read(path: str, limit: int = None) -> str:
    lines = safe_path(path).read_text().splitlines()
    if limit and limit < len(lines):
        lines = lines[:limit] + [f"... ({len(lines) - limit} more lines)"]
    return "\n".join(lines)[:50000]

📍 5.10 extract_text() — 文本提取工具

def extract_text(content) -> str:
    if not isinstance(content, list):
        return ""
    texts = []
    for block in content:
        text = getattr(block, "text", None)
        if text:
            texts.append(text)
    return "\n".join(texts).strip()

相比 s04 在主循环中直接 hasattr(block, "text")，s05 把它提取为可复用函数，更健壮（用 getattr + 判空 + join）。

6 类 vs 实例：每个 skill 对应一个 SkillDocument

常见困惑：SkillDocument 是个类（模板），它的所有实例是不同的对象，每个对象有自己的属性值。

📍 关键区分

# SkillDocument 是类（模板/蓝本）
# 每次 SkillDocument(manifest=..., body=...) 都创建一个新实例

实例 #1: SkillDocument(
    manifest=SkillManifest(name="code-review", description="审查代码", ...),
    body="Code review guidelines..."
)
实例 #2: SkillDocument(
    manifest=SkillManifest(name="test-gen", description="生成测试", ...),
    body="Test generation tips..."
)
实例 #3: SkillDocument(
    manifest=SkillManifest(name="refactor", description="重构建议", ...),
    body="Refactoring strategies..."
)

📍 循环 3 次后的字典状态

self.documents = {
    "code-review": SkillDocument(  ← 实例 #1
        manifest=SkillManifest(name="code-review", description="审查代码", path=Path("skills/code-review/SKILL.md")),
        body="Code review guidelines..."
    ),
    "test-gen": SkillDocument(  ← 实例 #2，不同的对象
        manifest=SkillManifest(name="test-gen", description="生成测试", path=Path("skills/test-gen/SKILL.md")),
        body="Test generation tips..."
    ),
    "refactor": SkillDocument(  ← 实例 #3，又不同的对象
        manifest=SkillManifest(name="refactor", description="重构建议", path=Path("skills/refactor/SKILL.md")),
        body="Refactoring strategies..."
    ),
}

类比：int 是一个类，但 int(1)、int(2)、int(3) 是不同的值。同一个类可以创建出无数个不同的实例。每个 skill 在字典中有一个 key-value 对，value 就是独立的 SkillDocument 对象。
