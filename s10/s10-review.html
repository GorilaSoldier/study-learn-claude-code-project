1 整体架构：6段组装流水线

核心思想：system prompt 不是一整块硬编码的字符串，而是由多个独立来源按清晰边界组装而成的"输入流水线"。

教学定位

s10 是一个汇合点：s05（skills）、s09（memory）都会汇进来。s10 不添加新的独立功能，而是把前几章长出来的功能组织成一份清晰的系统输入。

6 段结构总览

┌──────────────────────────────────────────────┐ │ 1. 核心指令 (core) 身份 + 行为准则 │ │ 2. 工具列表 (tools) 可用工具清单 │ │ 3. 技能元数据 (skills) .skills/ 目录 │ ← s05 汇入 │ 4. 持久记忆 (memory) .memory/ 目录 │ ← s09 汇入 │ 5. CLAUDE.md 指令链 三级规则文件 │ ├──────────────────────────────────────────────┤ │ === DYNAMIC_BOUNDARY === │ ← 静态/动态分界 ├──────────────────────────────────────────────┤ │ 6. 动态上下文 (dynamic) 日期/目录/模型/平台 │ └──────────────────────────────────────────────┘

为什么不能硬编码成一个大字符串

  1. 不好维护 — 哪段来自哪里？该改哪一部分？
  2. 不好测试 — 工具说明生成得对不对？memory 是否被正确拼入？
  3. 不好做缓存 — 稳定内容每轮重新生成浪费 token，临时内容又只该活一轮

方法 1：_build_core() — 核心指令（L54-59）

def _build_core(self) -> str:
    return (
        f"You are a coding agent operating in {self.workdir}.\n"
        "Use the provided tools to explore, read, write, and edit files.\n"
        "Always verify before assuming. Prefer reading files over guessing."
    )
  • 告诉模型：你是谁（coding agent）、在哪（workdir）、怎么干活（用工具验证）
  • 这是 prompt 的"宪法层"——所有行为约束的基础

方法 2：_build_tool_listing() — 工具清单（L61-69）

def _build_tool_listing(self) -> str:
    if not self.tools:
        return ""
    lines = ["# Available Tools"]
    for tool in self.tools:
        props = tool.get("input_schema", {}).get("properties", {})
        params = ", ".join(props.keys())
        lines.append(f"- {tool['name']}({params}): {tool['description']}")
    return "\n".join(lines)
  • 把工具列表格式化成 Markdown 列表，让模型知道它能调用什么
  • tool.get("input_schema", {}).get("properties", {}) 使用链式 get() 防御性地提取参数名，防止 KeyError

方法 3：_build_skill_listing() — 技能元数据（L71-93）

def _build_skill_listing(self) -> str:

        if not skill_md.exists():
            continue

  • 解析 frontmatter 提取 name 和 description

def _build_dynamic_context(self) -> str:
    lines = [
        f"Current date: {datetime.date.today().isoformat()}",
        f"Working directory: {self.workdir}",
        f"Model: {MODEL}",

3 build() — 总装车间与 DYNAMIC_BOUNDARY

代码位置：L167-213

def build(self) -> str:
    sections = []

    core = self._build_core()
    if core:
        sections.append(core)

    tools = self._build_tool_listing()
    if tools:
        sections.append(tools)

    skills = self._build_skill_listing()
    if skills:
        sections.append(skills)

    memory = self._build_memory_section()
    if memory:
        sections.append(memory)

    claude_md = self._build_claude_md()
    if claude_md:
        sections.append(claude_md)

    # Static/dynamic boundary
    sections.append(DYNAMIC_BOUNDARY)

    dynamic_context = self._build_dynamic_context()
    if dynamic_context:
        sections.append(dynamic_context)

    return "\n\n".join(sections)
关键理解：这里的"段"是构造时的逻辑单元（中间产物），不是最终产物的数量。build() 返回的确实是一个完整字符串，但内部的 6 个零件是独立加工的——就像生产一辆车，刹车系统和发动机各自独立制造。

DYNAMIC_BOUNDARY 的作用

DYNAMIC_BOUNDARY = "=== DYNAMIC_BOUNDARY ==="
  • 把静态段（1-5）和动态段（6）显式分隔
  • 真实 Claude Code 中，静态段可以跨轮缓存，只重新构建动态段
  • 模型注意力也能利用这个分隔符更好理解"固定规则 vs 实时信息"
教学版 vs 生产版：教学版每轮都全量重建 6 段。生产版只首次构建段 1-5，后续轮次复用缓存，只重新拼段 6，节省约 95%+ token。

4 meta 字典与 frontmatter 解析

代码位置：L80-98（_build_skill_listing）和 L103-118（_build_memory_section）

什么是 frontmatter

Markdown 文件头部用 --- 包裹的 YAML 风格元数据区域。

---
name: pdf
description: Generate PDF from markdown or HTML
version: 1.0
---

# PDF Skill
这是技能的实际内容...

meta 里存了什么

解析 frontmatter 得到的键值对字典：

meta = {
    "name": "pdf",          # 技能/记忆的名称
    "description": "Generate PDF from markdown or HTML",  # 简要描述
    "version": "1.0"       # 可选的额外字段
}

两个方法中 frontmatter 正则的差异

方法正则表达式提取内容
_build_skill_listingr"^---\s*\n(.*?)\n---"只提取 header 元数据
_build_memory_sectionr"^---\s*\n(.*?)\n---\s*\n(.*)"提取 header + body（正文）

区别：memory 文件需要在 system prompt 里呈现全文内容，而 skill 只需要告诉模型"有这个技能"就够了。

5 partition 与 "k, _, v" 详解

代码位置：L92-96

for line in match.group(1).splitlines():
    if ":" in line:
        k, _, v = line.partition(":")
        meta[k.strip()] = v.strip()

partition 与 split 的区别

方法输入输出
"name: pdf: v2".split(":")"name: pdf: v2"["name", " pdf", " v2"]（拆碎了）
"name: pdf: v2".partition(":")"name: pdf: v2"("name", ":", " pdf: v2")（只切第一刀）
为什么用 partition 而不是 split：description 里很可能包含冒号。用 split 会把内容拆散，而 partition 只切第一个冒号，后面的原封不动留给 value。解析 key-value 首选 partition。

_ 是什么？为什么不需要？

partition 返回三元组：(左边, 分隔符本身, 右边)

变量对应值需要吗？
k"name"（key 名）✅
_":"（分隔符自身）❌ 没有信息量
v" pdf"（value）✅

_ 不是语法关键字，Python 约定用它表示"丢弃这个值"。也可以写成 k, colon, v，但 colon 变量永远不会被用到，徒增 lint 警告。

6 Path.cwd() 用法

代码位置：L147

cwd = Path.cwd()

含义

Path.cwd() 是 pathlib 的类方法，返回当前工作目录，返回类型是 Path 对象。

写法返回类型说明
os.getcwd()str老式写法，字符串拼接路径麻烦
Path.cwd()Path新式写法，可直接用 / 拼接
例：Path.cwd() / "CLAUDE.md"

在这里的具体用途

判断"当前子目录 ≠ 项目根目录"，如果是，则多检查一级 cwd/CLAUDE.md：

cwd = Path.cwd()                        # 比如 /home/user/project/src
if cwd != self.workdir:               # workdir 是 /home/user/project
    subdir_claude = cwd / "CLAUDE.md"  # /home/user/project/src/CLAUDE.md
    if subdir_claude.exists():
        sources.append(...)
注意：Path.cwd() 是"真实"的当前目录，而 self.workdir 是用户传给 builder 的目录——两者可能不同（比如用户在子目录下执行命令）。

9 os.uname().sysname

代码位置：L172

f"Platform: {os.uname().sysname}"

含义

os.uname() 返回一个 named tuple，包含当前操作系统的信息：

字段含义Linux 示例macOS 示例
sysname操作系统名LinuxDarwin
nodename主机名my-serverMacBook-Pro
release内核版本6.8.024.3.0
version版本详情#1 SMP ...Darwin Kernel ...
machine硬件架构x86_64arm64
注意平台兼容性：os.uname() 在 Windows 上不可用。在 Claude Code 的上下文中 agent 通常只跑在 Linux/macOS 上，所以没问题。如果要跨平台，需要加 fallback。

目的：让模型知道自己是跑在 Linux 还是 macOS 上，从而在建议命令（ls vs dir）、路径写法等场景中做出正确的平台判断。

10 build_system_reminder() — 本轮提醒

代码位置：L214-227

def build_system_reminder(extra: str = None) -> dict:
    parts = []
    if extra:
        parts.append(extra)
    if not parts:
        return None
    content = "<system-reminder>\n" + "\n".join(parts) + "\n</system-reminder>"
    return {"role": "user", "content": content}

解决了什么问题

有些信息只在这一轮对话有效，比如：

  • "用户刚刚上传了一个文件"
  • "上一步操作出错了"
  • "当前正在处理的文件是 xxx"

如果把这些短命信息也塞进 system prompt，会破坏缓存策略，而且让 prompt 不断膨胀。

设计思路

把这些每轮变化的短命信息，伪装成一条 role: "user" 的消息发给模型，而不是混进 system prompt：

系统: [system prompt (稳定)] ← SystemPromptBuilder.build() 用户: <system-reminder> 上一步操作返回了错误，请注意 </system-reminder> 用户: 帮我修复这个问题 ← 用户的实际输入
system promptsystem reminder
寿命跨轮稳定（可缓存）仅本轮有效
存放位置system 参数user 消息
内容身份、规则、工具临时上下文、变动状态
小彩蛋：函数名 build_system_remider 拼错了，少了个 n，正确应为 build_system_reminder。教学代码里无伤大雅。

11 count("\n\n") — 段的计量

代码位置：L378

section_count = full_prompt.count("\n\n")

含义

build() 最后用 "\n\n".join(sections) 组装，所以 full_prompt 中的 \n\n 就是段与段之间的分隔符。这段代码统计了分隔符的个数。

n 段之间有 n-1 个分隔符，所以实际段数是 section_count + 1：

sections = ["段1", "段2", "段3"]
"\n\n".join(sections)  →  "段1\n\n段2\n\n段3"
"段1\n\n段2\n\n段3".count("\n\n")  →  2  # 分隔符个数
                     # 实际段数 = 2 + 1 = 3
不是精确计数：如果段内也有 \n\n，会被重复计入。这里只是用于调试日志的粗略统计，给一个 prompt 规模的量级参考，不是精确的段数计算。

启动时输出示例：

[System prompt assembled: 2847 chars, ~6 sections]

13 System Prompt 的本质：是每轮重建的"工作环境说明"，不是启动配置

关键理解

一句话：s10 的 system prompt 不是"启动时读一次就完了"的配置，而是每一轮对话都重新构建的工作环境说明。

看 agent_loop 的调用方式：

def agent_loop(messages: list) -> None:
    while True:
        system = prompt_builder.build()      # ← 每一轮都重新拼
        response = client.messages.create(
            model=MODEL, system=system,      # ← 每轮都传给模型
            ...
        )

更像"每天门口重印的员工手册"

手册内容对应段每天变吗？
"你是本公司员工"core — 身份❌
"公司内部系统目录"tools — 工具有哪些❌
"你有哪些专业证书"skills — 高级能力❌
"项目历史决策"memory — 跨会话记忆❌
"部门守则"CLAUDE.md — 指令链❌
---DYNAMIC_BOUNDARY---
"今天周几、你在哪个工位"dynamic — 日期/目录/平台✅ 每轮变化

三个角色

角色内容例子
身份设定告诉模型"你是谁"You are a coding agent operating in ...
环境描述告诉模型"你现在在哪"Current date: 2026-06-15
能力清单告诉模型"你能用什么"工具列表、skills、记忆、CLAUDE.md 规则

这个"每轮都重建"的设计保证了：新保存的记忆、新写的 CLAUDE.md、今天的日期，都能在下一轮立即生效。

14 静态段缓存的理论

教学版代码自己说了什么

# Static/dynamic boundary
sections.append(DYNAMIC_BOUNDARY)

# In real CC, the static prefix is cached across turns to save prompt tokens.

注释写得明明白白：真实的 Claude Code 里，静态前缀会被缓存。教学版没做缓存只是因为"缓存"不是本章的教学目标。

教学版 vs 生产版

教学版 s10真实生产版
每轮怎么拼从头调用 6 个 _build_xxx只重新拼段 6（动态部分）
段 1-5 怎么处理每次都重新构建首次构建后缓存起来
每轮传给 API 的 prompt[段1-5] ==BOUNDARY== [段6][缓存好的静态段] ==BOUNDARY== [段6]
token 开销每轮全量只有段 6 的变化量（约省 95%+)

教学版为什么不做缓存

教学页面明确说：

"不要先讲缓存与预算"

因为一旦引入缓存，就要处理：

  • 什么时候缓存失效？（.memory/ 变了？CLAUDE.md 被修改了？）
  • 缓存击穿 / 并发写入怎么办？
  • 怎么验证缓存和实时数据一致？

这些是复杂的基础设施问题。s10 的教学边界是：先把分段的概念立住。

你的直觉完全正确：静态部分（段 1-5）+ 动态边界 + 动态部分（段 6）的拆分，正是为了静态部分缓存，只有动态部分每轮重建。这个拆分方式本身，就是 s10 最核心的教学目标。

16 基础知识点汇总

1. dict.get(key, default) — 防御式取值

meta.get("name", skill_dir.name)   # 有 name 就用，没有就用 skill_dir.name 兜底

比直接 meta["name"] 安全，不会因 key 不存在而报 KeyError。

2. line.partition(":") — 只切第一刀

"name: pdf: v2".partition(":")  →  ("name", ":", " pdf: v2")

只切第一个分隔符，后面的原封不动。解析 key-value 的首选，比 split 更安全。

3. _ — 丢弃变量约定

Python 中用 _ 表示"这个位置有值但我明确不需要它"。不是语法关键字，是约定。

4. Path.cwd() — 当前工作目录

返回 Path 对象，可直接用 / 拼接路径。替代老式的 os.getcwd()。

5. Path.glob("*.md") — 文件模式匹配

类似 shell 的 ls *.md，返回生成器。常用 sorted() 转成排序后的列表。

6. Path.stem / Path.name — 文件名操作

属性示例（Path("prefer_tabs.md")）
.name"prefer_tabs.md"
.stem"prefer_tabs"
.suffix".md"

7. datetime.date.today() — 今天的日期

返回 date 对象，.isoformat() 输出 "YYYY-MM-DD" 格式字符串。

8. os.uname() — 系统信息

返回 named tuple：sysname, nodename, release, version, machine。教学版只用 .sysname（Linux / Darwin）。

9. "\n\n".join(sections) — 用空行拼接

用两个换行符（即一个空行）把各段拼接起来。反过来 .count("\n\n") 可以统计段间分隔符的数量。

10. re.match(r"^---\s*\n(.*?)\n---", text, re.DOTALL) — frontmatter 正则

re.DOTALL 让 . 能匹配换行符。(.*?) 是非贪婪匹配，确保只取第一个 --- 之前的内容。\s* 处理前后可能有的空白。

一句话记住 s10：system prompt 的关键不是"写一段很长的话"，而是"把不同来源的信息按清晰边界组装起来"。
