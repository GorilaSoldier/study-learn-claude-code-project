1 章节主旨

核心一句话：多个 Agent 同时在项目上干活时，用 git worktree 给每人一个独立目录 + 独立分支，文件不打架，git 不混乱。

解决了什么问题：s15-s17 解决了"谁干什么"（任务系统）和"怎么通信"（消息总线），但没解决 "在哪干"。Alice 和 Bob 都在同一个目录下工作——写同一个文件，互相覆盖；git log 里分不清谁的提交是谁的。

解决方案：每个任务绑定一个独立的 git worktree（独立目录 + 独立分支），队友认领任务后自动切到对应目录工作。完成后安全回收。

课程原话："各干各的目录, 互不干扰" — 任务管目标, worktree 管目录, 按 ID 绑定。

核心转变

s17: Alice & Bob 都在项目根目录干活 → write_file 互相覆盖 s18: Alice → .worktrees/auth/ (分支 wt/auth) Bob → .worktrees/ui/ (分支 wt/ui) → 互不影响，各提各的分支

2 最小心智模型

整个 s18 的核心就是 worktree 生命周期管理：创建 → 绑定 → 工作 → 回收。

┌─────────────────────────────────────────────────────┐ │ Worktree 生命周期 │ │ │ │ 1. Lead: create_worktree("auth", task_id="t1") │ │ → 创建 .worktrees/auth/ + 分支 wt/auth │ │ → 绑定到任务 t1 │ │ │ │ 2. Lead: spawn_teammate("Alice", ..., task="t1") │ │ │ │ 3. Alice: claim_task("t1") │ │ → 自动切换 cwd 到 .worktrees/auth/ │ │ → bash/read/write 都在 auth/ 下执行 │ │ → git add + git commit → 提交到 wt/auth 分支 │ │ │ │ 4. Alice: complete_task("t1") │ │ → cwd 恢复默认 │ │ │ │ 5. Lead: 审查代码 → git merge wt/auth → 合并到 main │ │ │ │ 6. Lead: remove_worktree("auth") │ │ → 安全检查 → 删除目录 + 分支 │ └─────────────────────────────────────────────────────┘

3 s17 的痛点：为什么需要隔离

核心问题：多个 Agent 在同一个目录下干活，文件相互覆盖，git 历史混乱。

看这个场景：

# s17 中，两个 Teammate 共享项目根目录

# Alice 的任务：重构认证模块
write_file("src/config.py", "AUTH_KEY = 'new_key'")

# Bob 的任务：重构 UI 登录页
write_file("src/config.py", "UI_THEME = 'dark'")

# 结果：Alice 的改动被 Bob 覆盖了！
# 而且 git log 分不清谁的提交是谁的
痛点具体表现
文件冲突两人改同一个文件，后写的覆盖先写的
git 混乱提交混在同一个分支，分不清谁是谁
一损俱损一个人的代码写崩了回滚，另一个人也被拖累
无法并行一个人 git commit 后，另一个人必须 git pull 才能继续

s18 的解法：给每个人一个独立的"工位"——每个 Teammate 拥有自己的目录和分支，各改各的。

4 Git Worktree 是什么

一句话：Git Worktree 是 Git 自带的"多工作区"功能（v2.5+, 2015年），让你能在同一仓库里同时签出多个分支到不同目录。

没有 worktree 时

你只有一个工作目录，每次 git checkout 切换分支，目录里的所有文件会被替换。

# 只有一个"工作台"
cd /project
git checkout main
# ...改改改...
git checkout -b hotfix        # 切分支！目录内容全变了
# 之前 main 的上下文丢了

有 worktree 时

每个目录"锁定"一个分支——进去就在那个分支上，不需要切换。

# 多个"工作台"，各管各的
cd /project                   # 这是 main 分支
git worktree add ../hotfix -b hotfix/v2 HEAD  # 创建新工作台
cd ../hotfix                  # 这是 hotfix/v2 分支
# ...改改改...
cd /project                   # 切回来，main 还是 main
# 两个目录互不干扰

Worktree vs Clone 对比

方面git worktree addgit clone
创建时间~10ms~10秒（大项目）
磁盘占用项目大小 + 工作文件项目大小 × 2（两份完整 .git）
提交关系共享 .git，互相可见完全独立，需手动 push/fetch
适用场景短生命周期任务长期独立开发

git worktree add 命令拆解

git worktree add .worktrees/auth -b wt/auth HEAD
部分说明
worktree add创建新工作目录
.worktrees/auth新目录路径
-b wt/auth同时创建 wt/auth 分支并签出
HEAD基于当前提交创建
注意：git worktree add 是 Git 原生命令，不是第三方工具。你可以直接在终端敲 git worktree --help 查看帮助。

5 Worktree 目录结构详解

完整目录树

/home/user/my-project/              ← 项目根目录（main 分支的工作区）
  ├── src/
  │   ├── main.py
  │   └── utils.py
  ├── .git/                          ← 唯一的 .git 对象存储（所有分支共享）
  ├── .tasks/                        ← 任务系统
  │   ├── task_xxx.json
  │   └── task_yyy.json
  └── .worktrees/                    ← 所有 worktree 集中管理
       ├── auth/                     ← wt/auth 分支的工作区
       │   ├── src/
       │   │   ├── main.py           ← 和根目录的 main.py 可以不同！
       │   │   └── auth.py
       │   └── .git                  ← 指向主仓库的指针文件
       └── ui/                       ← wt/ui 分支的工作区
           ├── src/
           │   ├── main.py
           │   └── ui.py
           └── .git                  ← 也是指针文件

关键理解

概念解释
.worktrees/auth/ 在根目录里吗？物理上在（project/.worktrees/auth/），但 Git 把它当作一个独立工作区
它和 src/ 是嵌套关系吗？不是。.worktrees/auth/src/ 和 project/src/ 是不同分支的内容，互不相关
里面的 .git 是啥？是一个文件（不是文件夹），内容类似 gitdir: /project/.git/worktrees/auth，指向主仓库
共享 .git 的好处？省空间（不重复存历史）、创建快（毫秒级）、对象互通（所有分支的 commit 互相可见）
比喻理解：就像你家院子里有个独立小房子——虽然在你的院子里，但它是另一个独立空间。Worktree 也是——虽然文件夹在项目根目录里，但它是一个独立的 git 工作区，有自己的固定分支。

代码中的定义

WORKTREES_DIR = WORKDIR / ".worktrees"   # project/.worktrees/
WORKTREES_DIR.mkdir(exist_ok=True)        # 相当于 mkdir -p

时间线 → ─────── [创建阶段] 你输入: "实现登录功能和注册功能" Lead: create_task("实现登录功能") → task_1 Lead: create_task("实现注册功能") → task_2 Lead: create_worktree("auth", task_id="task_1") → .worktrees/auth/ + wt/auth Lead: create_worktree("ui", task_id="task_2") → .worktrees/ui/ + wt/ui Lead: spawn_teammate("Alice", "coder", ...) Lead: spawn_teammate("Bob", "coder", ...) [工作阶段] Alice: claim_task → cwd 自动切换到 .worktrees/auth/ Alice: write_file("src/auth.py", ...) → 在 auth/ 目录写 Alice: bash("git add . && git commit") → 提交到 wt/auth 分支 Alice: complete_task → cwd 恢复 Bob: claim_task → cwd 自动切换到 .worktrees/ui/ Bob: write_file("src/ui.py", ...) → 在 ui/ 目录写 Bob: bash("git add . && git commit") → 提交到 wt/ui 分支 Bob: complete_task → cwd 恢复 [审查&合并阶段] ← 这段代码没实现，靠人工 Lead: git diff main..wt/auth → 看 Alice 改了啥 Lead: git checkout main Lead: git merge wt/auth → 合并到主分支 Lead: git merge wt/ui [清理阶段] Lead: remove_worktree("auth") → 安全检查 → 删除 .worktrees/auth/ + 分支 wt/auth Lead: remove_worktree("ui") → 安全检查 → 删除 .worktrees/ui/ + 分支 wt/ui
注意：代码只实现了创建、绑定工作和安全回收。中间的审查、合并、推送是 Lead（人类或 AI）手动操作的。自动合并代码太危险了，边界设定合理。

7 核心函数逐段详解

7.1 validate_worktree_name — 名称校验

def validate_worktree_name(name: str) -> str | None:
    if not name:
        return "Worktree name cannot be empty"
    if name == "." or name == "..":
        return f"'{name}' is not a valid worktree name"
    if not VALID_WT_NAME.match(name):
        return "Invalid worktree name ..."
    return None  # None = 校验通过
校验项目的
not name空字符串 → 拒绝
"." / ".."防范路径遍历攻击，防止 name="." 导致误删父目录
VALID_WT_NAME 正则只允许字母、数字、点、下划线、短横线，1-64字符

返回风格：返回 str | None——不返回布尔值，而是直接返回错误信息（有错）或 None（通过）。调用方直接用 if err: return f"Error: {err}"。

7.2 run_git — Git 命令执行器

def run_git(args: list[str]) -> tuple[bool, str]:
    try:
        r = subprocess.run(["git"] + args, cwd=WORKDIR,
                           capture_output=True, text=True, timeout=30)
        out = (r.stdout + r.stderr).strip()
        out = out[:5000] if out else "(no output)"
        return r.returncode == 0, out
    except subprocess.TimeoutExpired:
        return False, "Error: git timeout"
参数/片段解释
["git"] + args拼接命令，如 run_git(["worktree", "add", ...]) → ["git", "worktree", "add", ...]
capture_output=True捕获 stdout 和 stderr，不打印到屏幕
text=True输出为字符串（而非 bytes）
timeout=3030 秒超时，防止 git 卡死
r.stdout + r.stderrgit 有些信息走 stderr（如进度），两个都拿更保险
out[:5000]输出截断到 5000 字符，防止撑爆内存
r.returncode == 0返回码为 0 → True（成功），否则 False
关于 subprocess.run：这是 Python 标准库（不需要 pip 安装），用于执行外部命令。返回一个 CompletedProcess 对象，主要属性：returncode（退出码，0=成功）、stdout（标准输出）、stderr（标准错误）。

7.3 log_event — 事件日志

def log_event(event_type: str, worktree_name: str, task_id: str = ""):
    event = {"type": event_type, "worktree": worktree_name,
             "task_id": task_id, "ts": time.time()}
    with open(WORKTREES_DIR / "events.jsonl", "a") as f:
        f.write(json.dumps(event) + "\n")

JSONL 格式（JSON Lines）：每一行一个 JSON 对象，用换行分隔。优势是 append-only 追加写入（open("a")），不用读整个文件。

事件类型：create（创建）、remove（删除）、keep（保留）。

7.4 create_worktree — 创建 Worktree（核心）

def create_worktree(name: str, task_id: str = "") -> str:
    err = validate_worktree_name(name)       # 1. 校验名称
    if err:
        return f"Error: {err}"
    path = WORKTREES_DIR / name              # 2. 计算路径
    if path.exists():                        # 3. 防重复创建
        return f"Worktree '{name}' already exists"
    ok, result = run_git([                   # 4. 执行 git worktree add
        "worktree", "add", str(path), "-b", f"wt/{name}", "HEAD"
    ])
    if not ok:
        return f"Git error: {result}"
    if task_id:                              # 5. 可选绑定到 task
        bind_task_to_worktree(task_id, name)
    log_event("create", name, task_id)       # 6. 记录事件
    return f"Worktree '{name}' created at {path}"

关于 if task_id:：task_id 的默认值是空字符串 ""。在 Python 中，空字符串被视为 False，非空字符串为 True。所以不传 task_id 就只建目录，不绑定任务。

def bind_task_to_worktree(task_id: str, worktree_name: str):
    task = load_task(task_id)
    task.worktree = worktree_name    # 给 task 设置 worktree 字段
    save_task(task)                  # 持久化到 .tasks/task_xxx.json

绑定不改任务状态——任务仍是 pending，等队友认领才推进到 in_progress。这样 Lead 可以提前建好 worktree，队友 idle 时自然认领。

7.5 _count_worktree_changes — 变更检测

def _count_worktree_changes(path: Path) -> tuple[int, int]:
    try:
        r1 = subprocess.run(["git", "status", "--porcelain"],
                            cwd=path, capture_output=True, text=True, timeout=10)
        files = len([l for l in r1.stdout.strip().splitlines() if l.strip()])

        r2 = subprocess.run(["git", "log", "@{push}..HEAD", "--oneline"],
                            cwd=path, capture_output=True, text=True, timeout=10)
        commits = len([l for l in r2.stdout.strip().splitlines() if l.strip()])
        return files, commits
    except Exception:
        return -1, -1
这是最让初学者困惑的函数——逐行拆解：

r1 和 files（检查"改了没存"）：

# git status --porcelain 输出示例：
# " M app.py"    → 已修改，未暂存（没 git add）
# " D old.py"    → 已删除，未暂存
# "?? new.py"    → 新文件，未跟踪（git 不认识它）

# r1.stdout.strip().splitlines() 把输出按行拆成列表
# [l for l in ... if l.strip()] 过滤空行
# len(...) 数行数 → files = 有几行就有几个变更文件

r2 和 commits（检查"存了没推"）：

# git log @{push}..HEAD --oneline
# @{push} = 上次推送到远程的位置
# @{push}..HEAD = 从上次推送到现在之间的所有 commit
# --oneline = 每个 commit 只显示一行
# len(...) = 有几行就有几个未推送的 commit
变量执行命令计的是什么
r1 → filesgit status --porcelain未暂存/未跟踪的文件数
r2 → commitsgit log @{push}..HEAD --oneline未推送的提交数

Git 文件状态速查：

状态含义是否被 --porcelain 统计
未跟踪（untracked）新建文件，git 从没见过✅ ?? filename
已修改未暂存（modified）改过但没 git add✅ M filename
已暂存（staged）git add 了但没 commit✅ M filename
已提交（committed）git commit 过了❌ 不算"变更"
关于 @{push}：是 Git 的引用语法，表示"上游分支最后一次成功推送的位置"。@{push}..HEAD 就是"已提交但尚未推送到远程的所有 commits"。

7.6 remove_worktree — 安全回收

def remove_worktree(name: str, discard_changes: bool = False) -> str:
    err = validate_worktree_name(name)
    if err:
        return err
    path = WORKTREES_DIR / name
    if not path.exists():
        return f"Worktree '{name}' not found"

    if not discard_changes:               # 安全检查（默认开启）
        files, commits = _count_worktree_changes(path)
        if files < 0:                      # 检查本身失败（如 git 超时）
            return "Cannot verify ... force removal."
        if files > 0 or commits > 0:        # 有未提交 或 未推送 → 拒绝
            return "has X files and Y commits ... discard or keep."

    # 安全检查通过后，执行删除
    ok1, _ = run_git(["worktree", "remove", str(path), "--force"])
    run_git(["branch", "-D", f"wt/{name}"])   # 删分支
    log_event("remove", name)                    # 记录日志
    return f"Worktree '{name}' removed"

安全策略决策树：

remove_worktree(name, discard_changes=False)
    │
    ├── discard_changes=True  → 跳过检查，直接删除
    │
    └── discard_changes=False → 执行检查
         ├── 检查失败（files < 0）  → "无法验证，加 force 吧"
         ├── 有变更（files>0 或 commits>0） → "有改动，加 force 或 keep"
         └── 无变更（files=0 且 commits=0） → ✅ 允许删除

7.7 keep_worktree — 保留审查

def keep_worktree(name: str) -> str:
    err = validate_worktree_name(name)
    if err:
        return err
    log_event("keep", name)        # 只记录日志，不动文件
    return f"Worktree '{name}' kept for review"

什么都不做——只是记录一个 keep 事件到日志。语义是："这个 worktree 我不自动清理了，留给人工审查。"

8 Teammate cwd 自动切换机制

队友认领带 worktree 的任务时，bash、read_file、write_file 自动在 worktree 目录下执行。

核心代码

# 每个队友线程维护一个 wt_ctx 字典
wt_ctx = {"path": None}

def _wt_cwd() -> Path | None:
    p = wt_ctx["path"]
    return Path(p) if p else None

def _run_bash(command: str) -> str:
    return run_bash(command, cwd=_wt_cwd())  # 在 worktree 目录执行

def _run_read(path: str) -> str:
    return run_read(path, cwd=_wt_cwd())     # 在 worktree 目录读

def _run_write(path: str, content: str) -> str:
    return run_write(path, content, cwd=_wt_cwd())  # 在 worktree 目录写

切换时机

# 认领任务时检查是否有 worktree 绑定
def _run_claim_task(task_id: str):
    result = claim_task(task_id, owner=name)
    if "Claimed" in result:
        task = load_task(task_id)
        if task.worktree:                                   # 有绑定？
            wt_ctx["path"] = str(WORKTREES_DIR / task.worktree)   # → 切过去
        else:
            wt_ctx["path"] = None                                # → 用默认
    return result

# 完成任务时恢复 cwd
def _run_complete_task(task_id: str):
    result = complete_task(task_id)
    wt_ctx["path"] = None                                   # 恢复默认
    return result
认领前: wt_ctx["path"] = None → bash/read/write 在项目根目录执行 认领后: wt_ctx["path"] = ".worktrees/auth/" → bash/read/write 在 auth/ 下执行 完成后: wt_ctx["path"] = None → 恢复默认

10 常见困惑与 FAQ

Q：这不就是创了个文件夹吗？跟分支有什么关系？

A：既是文件夹也是分支。 git worktree add 同时做了两件事：创建文件夹 .worktrees/auth/ + 创建分支 wt/auth，并在这个文件夹里签出该分支。文件夹是工作区，里面签出的是独立分支。两者缺一不可。

Q：每个 Agent 单独创一个分支？

A：对。 分支以 wt/ 为命名空间前缀（如 wt/auth、wt/ui），所有操作都在 worktree 目录里，对应 wt/ 分支。Lead 审查后合并到 main，然后删除 worktree 和分支。

Q："多个工作台，不需要切换分支"是什么意思？

A：普通 git 你只有一个工作目录，git checkout 会替换所有文件。有 worktree 后，每个目录"锁定"一个分支——进 auth/ 就是 wt/auth，进根目录就是 main，不需要 git checkout 切来切去。

Q：.worktrees/auth/ 在项目根目录里吗？它和 src/ 是什么关系？

A：物理上 .worktrees/auth/ 在项目根目录里面（project/.worktrees/auth/），但它是独立的工作区。project/src/ 是 main 分支的内容，.worktrees/auth/src/ 是 wt/auth 分支的内容，两者可以完全不同，互不干扰。

Q：合并后 worktree 文件夹直接删了就行？代码会丢吗？

A：不会丢。 代码实际上存在 .git/objects/ 里（commit 对象）。worktree 里的文件只是工作区副本。一旦 git merge 把 commit 合进了 main，内容就在 git 历史里了。删掉 worktree 文件夹不影响任何已提交的代码。

Q：stdout 和 stderr 有什么区别？

A：这是 Linux 进程的两个输出通道。stdout（文件描述符 1）走正常输出，stderr（文件描述符 2）走错误/诊断信息。git 有些信息走 stderr（如 git push 的 "Everything up-to-date"），所以代码里 r.stdout + r.stderr 两个都拿。

Q：task_id 还有不存在的情况吗？

A：有。 函数签名 def create_worktree(name: str, task_id: str = "") -> str: 中 task_id 默认是空字符串。不传就不绑定，只建 worktree 做实验用。传了就同时绑定到任务。

Q：merge 的代码在哪？我没看到啊

A：没有实现。 s18 只实现了 worktree 的创建、工作、安全回收。中间的审查（git diff）、合并（git merge）、推送（git push）需要 Lead 手动操作。这是合理的设计——自动合并代码风险太高。

Q：remove_worktree 里的 name 一般是什么？哪来的？

A：由外部传入的。 可以是手动指定的字符串（"auth"、"ui"），也可以来自任务的 task.worktree 字段，或者来自事件日志的批量清理。不是代码自动生成的。
